## 6. Materiais de Apresentação Preparados

A apresentação está prevista para **26/11/2026**. Os materiais cobrem todos os 8 itens exigidos:

### 1. Estrutura profissional dos slides
- 18 slides em formato 16:9
- Capa, introdução, justificativa, objetivos, metodologia, fundamentação, arquitetura, tecnologias, backend, banco de dados, app visitante, mapas 2D/3D, rotas acessíveis, painel admin, testes, resultados, limitações, conclusão, perguntas
- Orientações de fonte, cores, tamanho e quantidade de bullet points por slide

### 2. Conteúdo organizado slide por slide
- Texto na tela para cada slide
- Elementos visuais sugeridos (imagens da pasta evidence/)
- Tempo alocado por slide (total ~15-20 min de apresentação)

### 3. Roteiro completo de fala
- Texto completo para ser lido/falado em cada slide
- Tempo total estimado: ~25 minutos (incluindo margem)
- Instruções de compressão se o tempo for excedido

### 4. Explicação da arquitetura e tecnologias
- Princípio central: separação API (navegação) × Blender (geometria) × contrato de cena
- Estrutura do monorepo com todas as pastas
- Endpoints da API FastAPI com descrição
- Algoritmo de Dijkstra e revisão do shopping
- Modelo de dados (8 entidades)
- Tecnologias: FastAPI, SQLAlchemy, Expo, React/Vite, Three.js, Blender, QR Code, AsyncStorage

### 5. Explicação dos principais diferenciais
1. Separação clara API × Blender com contrato de cena
2. QR Codes de baixo custo sem beacons/sensores
3. Mapas 2D e 3D consistentes (norte sempre para cima)
4. Rotas acessíveis (elevador, sem escadas)
5. Simulação identificada (modo demonstração)
6. Auditoria administrativa com motivo obrigatório
7. Fallback 2D quando 3D falha

### 6. Sequência de demonstração prática
8 passos: abertura/tela inicial → busca/destino → cálculo de rota/mapa → troca de piso/rota acessível → simulação → confirmação de chegada → painel admin → encerramento
- Script de contingência para problemas comuns
- Pré-requisitos e URLs de acesso

### 7. Perguntas da banca e respostas técnicas
- 23 perguntas organizadas por categoria (arquitetura, tecnologias, funcionalidades, banco, testes, QR, limitações)
- Orientações para responder perguntas desconhecidas (seja honesto, aponte para documentação, não invente)

### 8. Orientações para apresentar sem improvisação
- Seguir o roteiro passo a passo
- Não clicar em itens não planejados
- Manter a calma em caso de erro
- Não inventar funcionalidades
- Usar capturas da pasta evidence/ como backup
- Testar o ambiente antes da apresentação
